Durable Workflow CLI 2.9.0

## Start a local Server with only `dw` installed

2.9.0 adds `dw server:start-dev` (cli#161, cli#160). The native Server and a bundled
SQLite database are compiled into `dw`, so you need nothing else to start a local
runtime: no PHP, Docker, Redis, separate Server installation or runtime download.

```bash
dw server:start-dev
# in another terminal
dw env:set local --server=http://127.0.0.1:8080 --token=dev-token --make-default
dw doctor
```

- **It works from an empty directory.** The command creates the schema and the
  default namespace, then runs its own timers and maintenance. Your application
  workers still run workflow and activity code through an SDK.
- **It is local by design.** It binds only to loopback (`127.0.0.1` by default;
  `--host=localhost` and `--host=::1` also work) and refuses any other address.
  `--port=0` picks a free port and prints the URL it chose.
- **Authentication is on.** The default development bearer token is
  `dev-token`. `--token` sets a custom token, which is never printed.
- **Data persists.** It is stored in `dev-server` beside the CLI config file;
  `--data-dir` picks another directory. Only one development Server can use a
  directory at a time. The command refuses shared, linked or replaced data
  directories and files. It never takes over or upgrades an unrelated PHP
  Server database.
- **Ctrl+C stops it cleanly** and keeps its data.

The embedded engine is the native Server from accepted source `3d90086f`. That
is Server main after 3.11.0, including portable storage admission for library
builds. It is meant for development, not production; run a released Server
image for anything shared.

## Other changes

- The CLI now uses the published Rust SDK **4.18.0** (was 4.12.0), built without
  its `msrv-1-86` default feature so it can share the native Server's Avro
  dependency. Command behavior is unchanged apart from `server:start-dev`.
- Building from source needs Rust 1.99.
- CI pins the repaired central PHP bootstrap (durable-workflow/.github#400). This
  doesn't change release artifacts.
