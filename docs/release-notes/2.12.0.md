Durable Workflow CLI 2.12.0

## Guarded worker build and task queue retirement

Two new commands use the native Server's guarded retirement routes
(cli#172, durable-workflow/server#519):

```bash
# What still depends on an old build, or on every cohort of a queue
dw task-queue:retirement orders --build-id build-2026.04.20-a3f
dw task-queue:retirement orders --unversioned
dw task-queue:retirement orders

# Retire it once nothing does, bound to the revision you inspected
dw task-queue:retire orders --build-id build-2026.04.20-a3f --expected-revision=sha256:...
```

- `task-queue:retirement` is read-only. It lists each blocker with its exact
  count, up to 20 sample identities and a recovery action: pinned open runs,
  ready, leased and delayed tasks, open activities, pending update validations,
  schedules (queue scope only) and unattributed open runs. Unattributed runs
  make the inventory incomplete, and an incomplete inventory is never
  retirable. When the target is retirable, the output prints the matching
  `task-queue:retire` command with `--expected-revision`.
- `task-queue:retire` sends one guarded request and never resends it. The
  Server repeats the inventory inside its serialized transition. A refusal is
  HTTP 409 and changes nothing: `dw` prints the reason, each blocker with its
  samples and recovery, and the Server's expected resolution, then exits 2.
  `--expected-revision` refuses with `inventory_changed` if anything the
  inspection saw has changed.
- Both commands need a Server that advertises
  `capabilities.worker_build_retirement` (native Server 3.14.0 and later). On
  any other Server, `dw` exits 8 before sending a request.

Retirement complements `task-queue:drain`, which stops a build's polls
immediately whether or not work is still pinned to it. See the
[worker build rollout guide](https://durable-workflow.com/docs/polyglot/worker-build-id-rollout/#retire-a-build-or-queue)
for the promote, inspect, retire and recover journey.

## Unchanged

- No existing command, option, exit code or JSON shape changed.
- `dw server:start-dev` still embeds the same native Server as 2.11.0, and its
  data directory is unchanged.
- The CLI still uses the published Rust SDK 4.18.0. Building from source needs
  Rust 1.99.
- CI-only changes since 2.11.0 repin the PHP images and setup sources used by
  the legacy verification jobs.
