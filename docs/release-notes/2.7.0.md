Durable Workflow CLI 2.7.0

## Pause activity dispatch on a task queue

2.7.0 adds commands for native Server 3.8.0's activity dispatch pause
(server#577, cli#140). An operator can hold new activity work on one task queue
of one namespace, for example during a downstream outage, and resume it later.

```bash
dw task-queue:pause-activities orders --reason='payments vendor outage'
dw task-queue:activity-dispatch orders
dw task-queue:resume-activities orders
```

- **`task-queue:pause-activities`** pauses the queue, with an optional
  `--reason` of up to 1000 characters. If the queue was already paused, it
  reports the original pause and says the new reason was not recorded.
- **`task-queue:resume-activities`** resumes it, or reports that it was not
  paused.
- **`task-queue:activity-dispatch`** shows the state: who paused or resumed
  the queue, when, and why.
- **`task-queue:describe` and `task-queue:list`** show the state when the
  Server reports it.

While a queue is paused, no activity task on it is leased. Ready tasks keep
their attempt count, activity deadlines keep running, activities already
running finish, and workflow tasks, signals, queries and updates are delivered
as before. A pause is not a build drain: to stop one build's workers, use
`dw task-queue:drain`.

Each command sends one request and never resends it. The commands need a
Server that advertises `capabilities.task_queue_activity_dispatch_pause`
(native 3.8.0 or later). Against any other Server, including published PHP
Server 2.x, they exit with code 8 before sending anything, and describe and
list output is unchanged.

## Unchanged

Every other command behaves as in 2.6.0. A parity suite still compares `dw`
with the 2.x CLI on every change, offline and against published PHP Server
2.11.8 and native Servers 3.0.5 and 3.5.0. The 2.3.x PHAR line receives
security fixes only until 2027-02-28.
